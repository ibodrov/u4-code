# U4 Code

U4 Code is an independent fork of [T3 Code](https://github.com/pingdotgg/t3code) by T3 Tools Inc.
It is not affiliated with or endorsed by T3 Tools Inc.
It runs beside the official T3 Code desktop app on the same Linux account.
The two apps do not share application state, ports, URL schemes, or update feeds.
The upstream `LICENSE` and Git history stay unchanged.

## Maintaining the fork

`u4/main` is a short stack of topic commits on top of an upstream tag: identity, branding,
and one commit per feature (for example the oh-my-pi provider). To fix a topic, use
`git commit --fixup=<topic commit>` and `git rebase -i --autosquash`. Do not add many small
commits. Never merge upstream into `u4/main`; always rebase it.

To move to a newer upstream revision, prefer a stable or `preview` tag over a nightly:

```sh
packaging/u4/sync-upstream.sh v0.1.11        # rebases onto the tag on branch u4/sync-v0.1.11
```

The script leaves `u4/main` unchanged. It shows the `git range-diff` of the U4 patches and runs
`packaging/u4/check-identity.sh`. Git `rerere` is enabled, so a conflict that you resolved once
is resolved again automatically. After the checks and a build pass, fast-forward `u4/main`.

`check-identity.sh` counts official T3 identity values (`~/.t3` paths, `T3CODE_HOME`,
`com.t3tools`, `t3code`, "T3 Code") per file and compares them with
`packaging/u4/identity-baseline.tsv`. It fails when upstream adds new ones. Change each new match
to use `productIdentity.ts` or U4 text. If a match is deliberate, run the script with `--update`.

To keep rebases cheap, put U4-only files in `packaging/u4/`, `assets/u4/` and new `@u4code/*`
packages, and change upstream files only where a feature must be registered.

## Build

Prerequisites: Node 26, pnpm 12 (the repository pins its version), Rust with `cargo`, and FUSE 3 for the AppImage.

```sh
pnpm install --frozen-lockfile
node scripts/build-desktop-artifact.ts --platform linux --target AppImage --arch x64 \
  --build-version 0.1.10-u4.2 --output-dir release
```

The result is `release/U4-Code-<version>-x86_64.AppImage`.

## Install and start

```sh
packaging/u4/install.sh      # copies the newest release AppImage, adds the launcher and menu entry
u4code                       # starts U4 Code
```

`install.sh` writes only these files:

- `~/.local/share/u4code/U4-Code.AppImage`
- `~/.local/bin/u4code`
- `~/.local/share/applications/u4code.desktop`
- `~/.local/share/icons/hicolor/512x512/apps/u4code.png`

The `u4code` launcher removes inherited `T3CODE_*` variables, `ELECTRON_RUN_AS_NODE`,
and `/opt/t3code-bin` paths before it starts the AppImage.
Use it when you start U4 from a T3 Code terminal or agent.

## Separation from T3 Code

| Surface                                   | Official T3 Code                           | U4 Code                                                                          |
| ----------------------------------------- | ------------------------------------------ | -------------------------------------------------------------------------------- |
| Home and database                         | `~/.t3` (`T3CODE_HOME`)                    | `~/.u4` (`U4CODE_HOME`; `T3CODE_HOME` is ignored)                                |
| Electron profile and single-instance lock | `~/.config/t3code-v2`                      | `~/.config/u4code`                                                               |
| Compile cache                             | `~/.cache/t3code`                          | `~/.cache/u4code`                                                                |
| Capture helpers and backups               | `~/.local/share/t3code`                    | `~/.local/share/u4code`                                                          |
| Default server port                       | 3773                                       | 4773 (the app selects a free port if it is busy)                                 |
| URL schemes                               | `t3code`, `t3code-dev`                     | `u4code`, `u4code-dev`                                                           |
| App ID and window class                   | `com.t3tools.t3code`, `com.t3tools.T3Code` | `ca.ibodrov.u4code`, `ca.ibodrov.U4Code`                                         |
| URL handler entry                         | `com.t3tools.T3Code.desktop`               | `ca.ibodrov.U4Code.desktop`                                                      |
| Desktop control socket                    | `$TMPDIR/t3code-<uid>/`                    | `$TMPDIR/u4code-<uid>/`                                                          |
| systemd agent slices and scopes           | `app-t3code*.slice`, `t3code-*.scope`      | `app-u4code*.slice`, `u4code-*.scope`                                            |
| Boot service unit                         | `t3code.service`                           | `u4code.service`                                                                 |
| CLI command                               | `t3`                                       | `u4`: `~/.local/bin/u4` links to `~/.u4/bin/u4` (the app adds it at first start) |
| Managed policy file                       | `/etc/t3code/policy.json`                  | `/etc/u4code/policy.json`                                                        |
| Remote SSH device state                   | `~/.t3/device`                             | `~/.u4/device`                                                                   |
| Desktop auto-update                       | GitHub `pingdotgg/t3code`                  | Off. U4 has no feed and the updater is disabled in code.                         |
| Old profile import                        | Imports earlier T3 profiles                | Imports nothing                                                                  |

### Intentionally shared state

These items belong to other tools. Both apps use them:

- Provider CLIs and their configuration and sign-in, for example `~/.claude`, `~/.claude.json`, `~/.codex`, and `~/.cursor`.
- Git configuration, SSH keys, and the `gh` sign-in.
- The desktop secret store (KWallet on KDE). Each app uses its own entry, because the entry name comes from the app name.
- The T3 Connect cloud account, if you sign in to it from both apps.
- Repository worktrees and checkpoints that you open in both apps. Each app keeps its own records of them.
- The GNOME capture extension (`snap-shot@t3.codes`). Only one copy can be installed. It is not used on KDE.

## Name and icon

The web and desktop clients and the CLI help show "U4 Code" and the `u4` command.
Keep external T3 service and mobile app names, upstream links, license/attribution, and the GitHub star prompt unchanged.
Keep internal names, provider client names, checkpoint authors, file markers, and `t3code://pair`; model-facing text needs a separate change with evals.
The upstream `install`, `update`, and `uninstall` commands still manage the `t3` launcher and release archives.

The app icon is original artwork. Its source is `assets/u4/icon.svg`.
To change the icon, edit that file and run:

```sh
assets/u4/generate.sh        # needs rsvg-convert (librsvg) and node
```

The script writes the PNG and ICO files in `assets/u4/prod` and `assets/u4/dev`, and the web icons in `apps/web/public`.
The desktop build and `packaging/u4/install.sh` use `assets/u4/prod`. A development build uses the darker `assets/u4/dev` set.
See `assets/README.md` for the file list.

## Native oh-my-pi provider

U4 adds the optional `@u4code/provider-oh-my-pi` package, separate from upstream Pi and ACP.
It uses `omp --mode rpc-ui`, starts only U4-owned conversations, and stores their files beneath
U4's server state by provider instance. OMP credentials and profiles belong to OMP and remain
shared intentionally. See [oh-my-pi setup](docs/user/providers-oh-my-pi.md).

## Known gaps

- SSH and WSL remote environments still use upstream paths on the remote host
  (`$HOME/.t3/runtime`, `$HOME/.t3/ssh-launch`, `$HOME/.t3/wsl-runtime`) and download the
  upstream T3 server archive (`packages/ssh/src/tunnel.ts`,
  `apps/desktop/src/wsl/DesktopWslEnvironment.ts`). A U4 SSH remote therefore runs upstream T3
  and can share remote state with official T3 Code. A fix needs a U4 server archive to install.
- In the main checkout, `vp run dev` defaults to `~/.u4`, the real U4 state. Pass
  `--home-dir "$PWD/.t3"` there. Worktrees default to their own `.t3`. A first dev start in a
  worktree seeds its database read-only from `~/.t3/userdata`, which is deliberate.
